. How the CSRF Token Protects You
A CSRF token is a unique, secret, and unpredictable value generated by the server for the user's current session.

The Secret Handshake: When the server sends a form to the user, it includes this hidden token.

Validation: When the user submits the form, the server checks if the submitted token matches the one it issued.

1.Django is designed to serve HTML pages directly to a browser. However, for modern applications,
 we usually need to serve JSON data to mobile apps, React/Angular frontends, or other services.

2.
Serializers (The Biggest Reason)
In standard Django, your data is in "QuerySets" (Python objects). A browser or a mobile app cannot understand a Python object; it needs JSON.

3. Built-in Authentication & Permissions , admin panel 

JWT (JSON Web Tokens): Essential for mobile apps and stateless scaling.

OAuth2 Support: For "Login with Google/GitHub" features.

Granular Permissions: You can easily say, "Only the manager of this department can edit this record," with just one line of code (permission_classes).

4. ViewSets & Routers (Less Code)
In plain Django, you write a view for "List," another for "Detail," another for "Create."
In DRF, you use a ViewSet. It handles all CRUD (Create, Read, Update, Delete) operations in one class. When combined with a Router, 
it automatically generates all your URL patterns for you.

Statelessness means that the server does not store any information about the client's previous requests. 
Every single request from the client must contain all the information the server needs to understand and process it 
(like identity, credentials, and data)
